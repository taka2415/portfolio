Overview

Designed and implemented a 64-bit, 5-stage pipelined ARM CPU in SystemVerilog, with instruction fetch, decode, execute, memory, and write-back stages separated by pipeline registers. It builds on a register file, ALU, and single-cycle CPU designed earlier in the same series, then converted to a pipeline with full data forwarding and one delay slot after each load and branch.

The design goal was to keep the pipeline full: resolve data and control hazards in hardware so that stalls are the exception rather than the rule.

Design

  • Data forwarding: both the ALU result and the data memory output act as forwarding sources, and forwarded values feed every consumer of register data: the ALU, the branch logic, and the memory write path. Dependent instructions run back to back without waiting for write-back
  • Accelerated branch handling: branches are resolved early enough that a single delay slot covers them, so no instructions are flushed; the branch logic receives forwarded operands so a compare can depend on the instruction just ahead of it
  • Load handling: one delay slot after each load, consistent with the branch behavior
  • Forwarding corner cases: register 31 always reads as zero, so writes to it must never be forwarded; instructions that do not write a register must not trigger forwarding; and the destination register sits in different instruction fields depending on the format

ADDS and SUBS set the condition flags that B.LT tests (negative not equal to overflow), so flag state has to stay consistent with the forwarded data path. B, B.LT, and CBZ each execute one delay-slot instruction, and a value loaded by LDUR is not available to the instruction immediately after it.

Verification

  • Verified functional correctness at gate level through cycle-accurate simulation in ModelSim
  • Ran instruction-sequence test programs and checked the final register state
